# Reset All Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A "Reset all" button that empties the map, rewinds the journey timer to zero, and deletes the runs this browser tab saved, without touching runs saved by other tabs or browsers.

**Architecture:** Each browser tab owns a session id (kept in `sessionStorage`) and sends it with every `POST /api/simulate`. The backend already stores the whole request body in `runs.params` (JSONB), so the session id is persisted with no schema change. A new `DELETE /api/sessions/{session_id}/runs` removes that session's runs from the in-memory store and from Tiger Data (`runs` and `positions`). The frontend button resets local state at once and then calls the endpoint.

**Tech Stack:** FastAPI, Pydantic v2, psycopg 3 (backend); React 19, TypeScript, Vitest, Testing Library (frontend).

**Spec:** No separate spec file. The design was agreed in chat and is summarised in this header and in the task requirements below.

## Global Constraints

- Session ids match `^[A-Za-z0-9_-]+$` and are 1 to 64 characters long. The same rule applies in the request body and in the URL path.
- `sessionId` is optional on `POST /api/simulate` and `POST /api/compare`. Requests without it must behave exactly as today.
- No change to `backend/scripts/schema.sql`. The session id lives in `runs.params->>'sessionId'`.
- The `snapshots` and `current_samples` tables are never deleted from. The story/audio cache is not touched.
- A database problem never fails a request (existing rule in `backend/app/db.py`): the delete endpoint always answers 200 for a valid session id.
- JSON is camelCase on the wire, snake_case in Python (existing `ApiModel` rule).
- Backend tests on this Windows machine need a readable CA bundle. Run them from `backend/` in Git Bash as:
  ```bash
  TIDB_SSL_CA="$(./.venv/Scripts/python.exe -c 'import certifi; print(certifi.where())')" ./.venv/Scripts/python.exe -m pytest -q
  ```
  Baseline before this plan: 127 passed.
- Frontend checks run from the repo root: `npx vitest run` (baseline: 8 passed), `npm run lint`, `npm run build`.
- Work happens on branch `feature/reset-all`. Never push.

## Review Focus

1. A second browser tab resets while this tab has runs: this tab's runs must survive (covered by Task 1 test `test_delete_removes_only_that_sessions_runs`).
2. Database connected but failing or in its retry cooldown: the endpoint must say `failed`, not `unavailable`, so the user is told the saved runs remain (Task 1 tests for failure and cooldown).
3. A hostile or malformed session id in the URL or body (spaces, quotes, 65+ characters): rejected with 422 before any work (Task 1 parametrised tests).
4. `sessionStorage` unavailable (private mode, blocked site data, non-browser test environment): the tab still gets a usable session id (Task 2 runs in Vitest's node environment, where `sessionStorage` does not exist).
5. The delete request fails (backend down): the map still resets and the user sees a message saying the saved runs were not deleted (Task 3 `it.each` test).

@router.delete("/sessions/{session_id}/runs", response_model=DeleteRunsResponse)
def delete_session_runs(
    session_id: str = Path(min_length=1, max_length=64, pattern=SESSION_ID_PATTERN),
) -> DeleteRunsResponse:
    """Forget every run one browser session made: in memory and in Tiger."""
    mine = [run_id for run_id, owner in list(_run_sessions.items()) if owner == session_id]
    for run_id in mine:
        _runs.pop(run_id, None)
        _run_sessions.pop(run_id, None)
    if not db.configured():
        return DeleteRunsResponse(deleted=len(mine), database="unavailable")
    if db.available():
        try:
            return DeleteRunsResponse(deleted=db.delete_session_runs(session_id), database="cleared")
        except Exception:
            log.warning("run delete failed for session %s", session_id, exc_info=True)
            db.report_failure()
    return DeleteRunsResponse(deleted=len(mine), database="failed")

const SESSION_STORAGE_KEY = "littervoyage-session-id";

// One id per browser tab. sessionStorage keeps it across reloads, so runs saved before a
// reload can still be deleted; without storage the id lasts until the page is closed.
function loadSessionId(): string {
  try {
    const stored = sessionStorage.getItem(SESSION_STORAGE_KEY);
    if (stored && /^[A-Za-z0-9_-]{1,64}$/.test(stored)) return stored;
    const created = crypto.randomUUID();
    sessionStorage.setItem(SESSION_STORAGE_KEY, created);
    return created;
  } catch {
    return crypto.randomUUID();
  }
}

export const SESSION_ID = loadSessionId();
